## 1. Visão Geral

### 1.1 Objetivo
A aplicação de Quiz em TI é uma plataforma gamificada projetada para estudantes e profissionais de tecnologia testarem e aprimorarem seus conhecimentos em diversas áreas de TI. O sistema combina elementos de aprendizado com gamificação para criar uma experiência envolvente e educativa.

### 1.2 Tecnologias
- **Backend**: Flask (Python)
- **Frontend**: HTML5, CSS3, JavaScript (com possibilidade de framework como Vue.js)
- **Banco de Dados**: MySQL
- **Servidor Web**: Apache (XAMPP)
- **Autenticação**: JWT (JSON Web Tokens)

### 1.3 Principais Funcionalidades
- Sistema de autenticação e perfis de usuário
- Múltiplas categorias e níveis de dificuldade
- Diversos tipos de perguntas (múltipla escolha, resposta escrita)
- Sistema de pontuação, níveis e conquistas
- Ranking global e por categoria
- Painel administrativo para gerenciamento de conteúdo

## 2. Arquitetura do Sistema

### 2.1 Visão Geral da Arquitetura
A aplicação segue uma arquitetura cliente-servidor em camadas:

```
+------------------+     +------------------+     +------------------+
|                  |     |                  |     |                  |
|  Cliente         |<--->|  Servidor Flask  |<--->|  Banco de Dados  |
|  (Navegador)     |     |  (API REST)      |     |  (MySQL)         |
|                  |     |                  |     |                  |
+------------------+     +------------------+     +------------------+
```

### 2.2 Componentes do Sistema
1. **Camada de Apresentação**: Interface de usuário responsiva acessada via navegador
2. **Camada de Aplicação**: API REST implementada em Flask
3. **Camada de Serviços**: Lógica de negócio e processamento
4. **Camada de Acesso a Dados**: Interação com o banco de dados MySQL

### 2.3 Integração com Serviços Externos
- Serviço de e-mail para recuperação de senha e notificações
- Possibilidade de integração com redes sociais (login via Google, Facebook)
- Armazenamento de imagens para badges e avatares de usuários

## 3. Modelo de Dados

### 3.1 Diagrama de Entidade-Relacionamento

O banco de dados é composto pelas seguintes entidades principais:

- **Users**: Cadastro e informações dos usuários
- **Questions**: Banco de perguntas
- **Categories**: Categorias das perguntas
- **Difficulties**: Níveis de dificuldade
- **QuizSessions**: Sessões de quiz criadas pelos usuários
- **UserAnswers**: Respostas dadas pelos usuários
- **Badges**: Conquistas desbloqueáveis
- **Levels**: Níveis de progressão dos usuários

### 3.2 Relacionamentos Principais

- Um usuário pode participar de várias sessões de quiz (1:N)
- Uma sessão de quiz contém várias respostas de usuário (1:N)
- Uma pergunta possui uma categoria e uma dificuldade (N:1)
- Uma pergunta de múltipla escolha possui várias alternativas (1:N)
- Um usuário pode conquistar várias badges (N:M)
- Usuários acumulam pontos em diferentes categorias (N:M)

### 3.3 Tabelas e Campos Críticos

Veja detalhamento completo no script SQL fornecido anteriormente. Principais tabelas:

- `users`: Informações de usuário, autenticação e progresso
- `questions`: Repositório de perguntas com metadados
- `alternatives`: Opções para perguntas de múltipla escolha
- `written_answers`: Gabarito para perguntas de resposta escrita
- `quiz_sessions`: Registro de sessões de quiz
- `user_answers`: Histórico de respostas dos usuários
- `badges`: Conquistas disponíveis no sistema
- `user_badges`: Relação de badges conquistadas por usuários

## 4. Regras de Negócio

### 4.1 Autenticação e Perfil

#### 4.1.1 Registro de Usuário
- Nome completo, e-mail e senha são obrigatórios
- E-mail deve ser único no sistema
- Senha deve ter no mínimo 8 caracteres, incluindo letras e números
- Senha deve ser armazenada usando hash bcrypt

#### 4.1.2 Login
- Autenticação via e-mail e senha
- Criação de token JWT com validade de 24 horas
- Refresh token com validade de 7 dias
- Bloqueio temporário após 5 tentativas de login mal-sucedidas

#### 4.1.3 Recuperação de Senha
- Token único gerado e enviado por e-mail
- Validade de 1 hora para o token de recuperação
- Limite de 3 solicitações de recuperação por dia

### 4.2 Sistema de Quiz

#### 4.2.1 Seleção de Quiz
- O usuário escolhe uma categoria e nível de dificuldade
- O sistema seleciona 10 perguntas aleatórias (configurável) que atendam aos critérios
- Usuário não recebe perguntas que já respondeu corretamente (opcional, configurável)

#### 4.2.2 Resposta às Perguntas
- Tempo limite para resposta baseado na dificuldade:
  - Fácil: 30 segundos por pergunta
  - Médio: 20 segundos por pergunta
  - Difícil: 10 segundos por pergunta
- Temporizador opcional (pode ser desativado nas configurações)
- Feedback imediato após cada resposta

#### 4.2.3 Avaliação de Respostas
- **Múltipla Escolha**:
  - Comparação direta com o gabarito
  - Uma única alternativa correta

- **Resposta Escrita**:
  - Comparação case-insensitive com o gabarito
  - Suporte a respostas alternativas (sinônimos)
  - Tolerância a pequenos erros ortográficos (configurável)
  - Validação parcial para respostas parcialmente corretas

#### 4.2.4 Finalização do Quiz
- Exibição de pontuação total
- Cálculo da taxa de acerto (porcentagem)
- Exibição de badges conquistadas
- Atualização automática de ranking e nível

### 4.3 Sistema de Pontuação e Gamificação

#### 4.3.1 Cálculo de Pontos
- Pontuação base por pergunta:
  - Múltipla escolha:
    - Fácil: 10 pontos
    - Médio: 20 pontos
    - Difícil: 30 pontos
  - Resposta escrita:
    - Fácil: 15 pontos
    - Médio: 25 pontos
    - Difícil: 35 pontos

- Modificadores:
  - Bônus por tempo: +20% se responder antes de 50% do tempo limite
  - Bônus por sequência: +10% a cada 3 acertos consecutivos
  - Resposta parcial: 30-70% dos pontos (apenas para perguntas escritas)

#### 4.3.2 Sistema de Níveis
- Níveis baseados em pontuação total:
  - Iniciante: 0-99 pontos
  - Aprendiz: 100-499 pontos
  - Desenvolvedor: 500-999 pontos
  - Especialista: 1000-2499 pontos
  - Mestre: 2500-4999 pontos
  - Guru: 5000+ pontos

- Fórmula para cálculo de nível:
  ```
  nível = floor(pontos_totais / 100) + 1
  ```

#### 4.3.3 Sistema de Badges
- Categorias de badges:
  - Gerais (independentes de categoria)
  - Específicas por categoria (Python, SQL, etc.)
  - Por performance (acertos consecutivos, velocidade)

- Condições de conquista:
  - Pontuação total acumulada
  - Pontuação em categoria específica
  - Número de quizzes completados
  - Acertos consecutivos
  - Taxa de acerto (porcentagem)

#### 4.3.4 Sistema de Ranking
- Ranking global baseado em pontuação total
- Ranking por categoria (melhores em Python, SQL, etc.)
- Atualização em tempo real
- Exibição dos 10 melhores usuários (configurável)

### 4.4 Administração

#### 4.4.1 Gerenciamento de Perguntas
- CRUD completo (Criar, Ler, Atualizar, Excluir)
- Verificação de duplicidade
- Revisão de qualidade antes da publicação
- Desativação temporária de perguntas

#### 4.4.2 Gerenciamento de Usuários
- Visualização de todos os usuários
- Ativação/desativação de contas
- Reset de senha
- Visualização de estatísticas por usuário
- Remoção de pontos em caso de fraude

#### 4.4.3 Relatórios e Estatísticas
- Perguntas mais erradas
- Desempenho médio por categoria
- Taxa global de acertos
- Badges mais/menos conquistadas
- Tempo médio de resposta por dificuldade

## 6. API REST

### 6.1 Autenticação API

| Endpoint | Método | Descrição | Parâmetros | Resposta |
|----------|--------|-----------|------------|----------|
| `/api/auth/register` | POST | Registrar novo usuário | `name`, `email`, `password` | `user_id`, `token` |
| `/api/auth/login` | POST | Autenticar usuário | `email`, `password` | `token`, `refresh_token` |
| `/api/auth/refresh` | POST | Renovar token | `refresh_token` | `token`, `refresh_token` |
| `/api/auth/forgot-password` | POST | Solicitar reset de senha | `email` | `success`, `message` |
| `/api/auth/reset-password` | POST | Resetar senha | `token`, `new_password` | `success`, `message` |
| `/api/auth/logout` | POST | Invalidar token | `token` | `success` |

### 6.2 API de Usuário

| Endpoint | Método | Descrição | Parâmetros | Resposta |
|----------|--------|-----------|------------|----------|
| `/api/user/profile` | GET | Obter perfil do usuário | - | `user_data` |
| `/api/user/profile` | PUT | Atualizar perfil | `name`, `[avatar]` | `user_data` |
| `/api/user/change-password` | POST | Trocar senha | `current_password`, `new_password` | `success` |
| `/api/user/statistics` | GET | Obter estatísticas | `[category_id]` | `stats_data` |
| `/api/user/badges` | GET | Listar badges | - | `badges_list` |
| `/api/user/history` | GET | Histórico de quizzes | `[page]`, `[limit]` | `quiz_history` |

### 6.3 API de Quiz

| Endpoint | Método | Descrição | Parâmetros | Resposta |
|----------|--------|-----------|------------|----------|
| `/api/categories` | GET | Listar categorias | - | `categories` |
| `/api/difficulties` | GET | Listar dificuldades | - | `difficulties` |
| `/api/quiz/start` | POST | Iniciar quiz | `category_id`, `difficulty_id` | `session_id`, `questions` |
| `/api/quiz/question/:id` | GET | Detalhes da pergunta | - | `question_data` |
| `/api/quiz/answer` | POST | Enviar resposta | `session_id`, `question_id`, `answer_data`, `time` | `result`, `correct_answer` |
| `/api/quiz/complete` | POST | Finalizar quiz | `session_id` | `score`, `accuracy`, `badges_earned` |

### 6.4 API de Ranking

| Endpoint | Método | Descrição | Parâmetros | Resposta |
|----------|--------|-----------|------------|----------|
| `/api/ranking/global` | GET | Ranking global | `[limit]` | `ranking_data` |
| `/api/ranking/category/:id` | GET | Ranking por categoria | `[limit]` | `ranking_data` |
| `/api/ranking/position` | GET | Posição do usuário | `[category_id]` | `user_position` |

### 6.5 API de Administração

| Endpoint | Método | Descrição | Parâmetros | Resposta |
|----------|--------|-----------|------------|----------|
| `/api/admin/questions` | GET | Listar perguntas | `[page]`, `[filters]` | `questions_list` |
| `/api/admin/questions` | POST | Criar pergunta | `question_data` | `question_id` |
| `/api/admin/questions/:id` | PUT | Atualizar pergunta | `question_data` | `success` |
| `/api/admin/questions/:id` | DELETE | Remover pergunta | - | `success` |
| `/api/admin/users` | GET | Listar usuários | `[page]`, `[filters]` | `users_list` |
| `/api/admin/users/:id` | PUT | Atualizar usuário | `user_data` | `success` |
| `/api/admin/reports` | GET | Gerar relatórios | `report_type`, `[filters]` | `report_data` |

## 8. Segurança

### 8.1 Autenticação e Autorização
- Senhas armazenadas com bcrypt (fator de custo 12+)
- Tokens JWT com expiração curta (24 horas)
- Refresh tokens com rotação
- CSRF protection
- Verificação de permissões por rota

### 8.2 Proteção contra Vulnerabilidades Comuns
- SQLi: Uso de ORM e prepared statements
- XSS: Sanitização de input e output
- CSRF: Tokens anti-CSRF em formulários
- Injection: Validação rigorosa de input
- Brute force: Rate limiting e captcha
- Session fixation: Regeneração de sessão após login

### 8.3 Privacidade de Dados
- Coleta apenas de dados necessários
- Opção de exclusão de conta pelo usuário
- Criptografia de dados sensíveis
- Compliance com LGPD/GDPR (conforme aplicável)
- Logs de auditoria para acesso a dados

### 8.4 Segurança na Infraestrutura
- HTTPS obrigatório
- Headers de segurança apropriados
- Configuração segura do servidor web
- Backup regular do banco de dados
- Monitoramento de segurança

## Apêndice A: Exemplos de Implementação

### A.1 Exemplo de Cálculo de Pontuação

```python
def calculate_points(question, user_answer, response_time, consecutive_correct):
    # Pontos base por tipo e dificuldade
    base_points = question.base_points
    
    # Verificar se está correto
    if not user_answer.is_correct:
        return 0
    
    # Cálculo de bônus
    time_bonus = 0
    consecutive_bonus = 0
    
    # Bônus por tempo (se respondeu antes de 50% do tempo)
    if response_time and question.time_limit:
        if response_time <= (question.time_limit / 2):
            time_bonus = 0.2  # 20% de bônus
    
    # Bônus por sequência (10% a cada 3 acertos)
    consecutive_bonus = (consecutive_correct // 3) * 0.1
    
    # Cálculo final
    total_points = base_points * (1 + time_bonus) * (1 + consecutive_bonus)
    
    return round(total_points)
```
